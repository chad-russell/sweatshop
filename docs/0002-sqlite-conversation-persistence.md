# 0002 — Conversation persistence (SQLite)

Status: **proposed** — awaiting approval before implementation.

## Goal

Give sweatshop its own database: a SQLite store that indexes every
conversation and mirrors its event stream, with URL-addressed
conversations and a sidebar list. History survives any browser, any
device, and a cleared localStorage; the db becomes the foundation for
FTS/search and everything else the sqlite+S3 north star implies.

## Current state

- No app database. eve persists durable sessions internally under
  `.eve/.workflow-data/` (one JSON file per stream event) — that store
  drives resume but is not ours to query, has no index, and follows
  eve's own retention defaults.
- The only pointer to the current conversation is a localStorage cursor
  in the browser.

## Non-goals (v1)

- Search / FTS (the mirror enables it later; not built now).
- Rename, delete, archive, pagination in the sidebar.
- LLM-generated titles, summaries, tags.
- S3 object storage; multi-agent; Postgres (never).

## Decisions

| Decision     | Choice                                                            | Why                                                                    |
| ------------ | ----------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Engine       | `better-sqlite3` + `drizzle-orm`, drizzle-kit migrations          | Proven combo in the prototype; sync, single-file, no server            |
| Layout       | One db file: `data/sweatshop.db`, WAL, `busy_timeout`             | Split dbs come when a second subsystem earns one                       |
| Write path   | eve channel `events` observer hook (`agent/channels/eve.ts`)      | Server-side, transport-level: any client (browser, curl) persists      |
| Mirror       | Registry + append-only event mirror (raw JSON events)             | Enables FTS/inspection later; rules below make it derived, not a peer  |
| Titles       | First user message, trimmed to ~60 chars                          | Deterministic, free, instant                                            |
| Read path    | RSC reads SQLite directly for the list; transcripts replay from   | No API layer; single resume mechanism (eve stream replay, proven)      |
|              | eve's stream (`initialSession` + `resume: true`)                  |                                                                        |
| Routing      | `/` = new chat, `/c/[sessionId]` = conversation; sidebar list     | URL is the durable address; retires the localStorage cursor            |

## The dual-write rules (invariants)

The mirror is a **derived materialized view of eve's stream**, never a
second source of truth:

1. **One-way.** eve's durable stream is authoritative for everything
   behavioral — resume, cancel, continuation, compaction. Nothing the
   agent or runtime does ever reads the mirror. Divergence can only mean
   the copy missed something, never that the agent is wrong.
2. **Rebuildable.** Appends are keyed `(conversation_id, seq)` and
   idempotent; any conversation's mirror can be regenerated by replaying
   its stream from index 0. A rebuild procedure is defined and testable.
3. **Schema-insulated.** Events are stored as raw JSON with a loose
   `type` column. eve event-shape drift (preview software) degrades
   future features, never integrity.
4. **Failsafe.** Mirror write failures are logged and never break or
   delay the stream. Worst case is a hole in future search coverage.
5. **Auditable.** `conversations.max_seq` (and event count) makes gaps
   detectable rather than silent.
6. **The one exception:** if eve's retention ever prunes a session's run
   data, the mirror becomes the transcript of record — the only case
   where the derived copy outranks the source.

## Schema (drizzle)

```text
conversations
  id           text PK        -- eve sessionId (wrun_...)
  title        text
  created_at   integer        -- unix ms
  updated_at   integer        -- unix ms, bumped on each appended event
  max_seq      integer        -- highest mirrored seq (gap audit)

conversation_events
  conversation_id text FK -> conversations.id
  seq             integer    -- stream index
  type            text       -- loose event type
  event           text       -- raw JSON envelope
  at              integer    -- unix ms
  PK (conversation_id, seq)
```

Indexes: `conversations(updated_at desc)` for the sidebar.

## Write path detail

`agent/channels/eve.ts` gains an `events` observer:

- On session-creating flow / first `message.received`-bearing event:
  upsert the conversation row; title = first user message text trimmed
  to 60 chars (only when title is null).
- Every observed event: idempotent insert into `conversation_events`,
  bump `updated_at`/`max_seq` on success.
- All writes wrapped in the failsafe (try/catch → console.error with a
  stable prefix; never rethrow into the stream).

## Read path + UX

- `app/page.tsx` (`/`): new-chat landing (current chat surface, no
  session restore).
- `app/c/[sessionId]/page.tsx`: server component validates the id
  against `conversations`, renders the chat client with
  `initialSession = { sessionId, streamIndex: 0 }`, `resume: true`.
- Sidebar (server component, revalidated per navigation): New chat
  button + list (title, relative updated_at), active conversation
  highlighted. Layout becomes two-pane on md+, collapsible on mobile.
- The client drops localStorage persistence entirely (URL replaces
  cursor); `onSessionChange` navigates to `/c/[sessionId]` after the
  first send replaces the URL, per the generated-web-chat pattern.
- New chat navigates to `/`; it does not reset/delete the prior session,
  which remains at its URL.

## Environment / container

- `data/` gitignored; db lives in the bind mount (host-visible for
  backup).
- `npm run db:generate` (drizzle-kit generate) and
  `npm run db:migrate` (apply) run inside the container via `./dev exec`.
- Risk: better-sqlite3 needs a prebuilt binary for node 24 / trixie
  slim — first implementation step proves `npm install` in the
  container; fallback is `@libsql/client` (pure JS) with the same
  drizzle schema.

## Tests (first in repo)

Store-layer unit tests against a temp db file (vitest): idempotent
append, gap detection via `max_seq`, title-from-first-message, updated_at
bumping. No LLM is involved in this layer, so the mock-LLM rule is not
yet triggered — it activates with the first agent-behavior test.

3. `feat(web): /c/[sessionId] route with durable resume`

6. `docs: 0002 verification notes`

## Verification (definition of done)

- A conversation had via the browser appears in `data/sweatshop.db`
  (registry row + mirrored events) with no client cooperation.
- `/c/[sessionId]` on a fresh browser (no localStorage) replays the
  transcript and can continue it.
- Sidebar lists conversations across restarts of the container; New
  chat → `/`; reload of `/c/...` resumes.
- Mirror rules hold: killing the db mid-stream never breaks a turn;
  re-running the observer inserts nothing twice; `max_seq` matches the
  stream tail.
- `npm run typecheck` + `npm run lint` green; store tests pass in the
  container.
